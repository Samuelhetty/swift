# SwiftDeploy

A declarative container deployment tool. `manifest.yaml` is the single source of truth — `swiftdeploy` generates all configuration from it.

## Project Structure

```
swiftdeploy/
├── manifest.yaml          # ← only file you edit
├── swiftdeploy            # CLI tool (Python, executable)
├── Dockerfile             # API service image
├── app/
│   └── main.py            # HTTP API service
├── templates/
│   ├── nginx.conf.j2      # Nginx config template
│   └── docker-compose.yml.j2  # Compose template
├── nginx.conf             # generated by swiftdeploy init
├── docker-compose.yml     # generated by swiftdeploy init
└── README.md
```

## Prerequisites

- Docker & Docker Compose v2
- Python 3.8+ (for the CLI)
- `pyyaml` and `jinja2` (auto-installed by CLI if missing)

## Quick Start

### 1. Build the image

```bash
docker build -t swift-deploy-1-node:latest .
```

### 2. Run `init` to generate configs

```bash
./swiftdeploy init
```

### 3. Validate pre-flight checks

```bash
./swiftdeploy validate
```

### 4. Deploy the stack

```bash
./swiftdeploy deploy
```

The stack is live at: `http://localhost:8080`

## Subcommand Walkthrough

### `swiftdeploy init`

Parses `manifest.yaml` and renders:
- `nginx.conf` — Nginx reverse proxy config
- `docker-compose.yml` — full stack definition

```bash
./swiftdeploy init
```

### `swiftdeploy validate`

Runs 5 pre-flight checks:

| # | Check |
|---|-------|
| 1 | `manifest.yaml` exists and is valid YAML |
| 2 | All required fields are present and non-empty |
| 3 | Docker image from manifest exists locally |
| 4 | Nginx port is not already bound on host |
| 5 | Generated `nginx.conf` is syntactically valid (via `nginx -t`) |

Exits non-zero on any failure.

### `swiftdeploy deploy`

1. Runs `init`
2. Brings up the stack with `docker compose up -d`
3. Blocks until `/healthz` responds or 60s timeout

```bash
./swiftdeploy deploy
```

### `swiftdeploy promote [canary|stable]`

Switches deployment mode with a rolling restart:

1. Updates `mode` in `manifest.yaml` in-place
2. Regenerates `docker-compose.yml` with new `MODE` env var
3. Restarts only the `app` container
4. Confirms new mode via `/healthz`

```bash
./swiftdeploy promote canary
./swiftdeploy promote stable
```

### `swiftdeploy teardown [--clean]`

Stops and removes all containers, networks, and volumes.

```bash
./swiftdeploy teardown           # remove containers/volumes
./swiftdeploy teardown --clean   # also delete generated configs
```

## API Endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/` | Welcome message with mode, version, timestamp |
| GET | `/healthz` | Liveness check with uptime |
| POST | `/chaos` | Simulate degraded behaviour (canary only) |

### Chaos Modes (canary only)

```bash
# Slow: sleep N seconds before responding
curl -X POST http://localhost:8080/chaos \
  -H 'Content-Type: application/json' \
  -d '{"mode":"slow","duration":3}'

# Error: return 500 on ~50% of requests
curl -X POST http://localhost:8080/chaos \
  -H 'Content-Type: application/json' \
  -d '{"mode":"error","rate":0.5}'

# Recover: cancel active chaos
curl -X POST http://localhost:8080/chaos \
  -H 'Content-Type: application/json' \
  -d '{"mode":"recover"}'
```

## Nginx

- Listens on `nginx.port` (default: 8080)
- Proxy timeouts set from `nginx.proxy_timeout`
- JSON error bodies on 502/503/504
- `X-Deployed-By: swiftdeploy` header on all responses
- Forwards `X-Mode` header from upstream
- Access log format: `$time_iso8601 | $status | ${request_time}s | $upstream_addr | $request`

## manifest.yaml Reference

```yaml
services:
  image: swift-deploy-1-node:latest   # Docker image name
  port: 3000                          # Container port
  mode: stable                        # stable | canary
  version: "1.0.0"                    # APP_VERSION injected
  replicas: 1
  restart_policy: unless-stopped
  log_volume: swiftdeploy-logs

nginx:
  image: nginx:latest
  port: 8080                          # Host-facing port
  proxy_timeout: 30                   # Seconds
  contact: ops@swiftdeploy.io         # Shown in error bodies

network:
  name: swiftdeploy-net
  driver_type: bridge
```

## Security

- Service container runs as non-root `appuser`
- All Linux capabilities dropped (`cap_drop: ALL`)
- `NET_BIND_SERVICE` re-added only if needed
- Service port is never exposed directly — all traffic routes through Nginx
- Images are Alpine-based (< 300MB)
